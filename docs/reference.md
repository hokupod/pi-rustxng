# 動作と制約

## 対応環境

RustXNG v0.30.0 の公式 standalone executable を使用します。

| 環境                | 公式 artifact の target   |
| ------------------- | ------------------------- |
| macOS Apple Silicon | aarch64-apple-darwin      |
| macOS Intel         | x86_64-apple-darwin       |
| Linux x64           | x86_64-unknown-linux-musl |
| Linux arm64         | aarch64-unknown-linux-gnu |
| Windows x64         | x86_64-pc-windows-msvc    |

Linux arm64 は glibc 2.39 以上が必要です。Linux x64 は musl 版を選択します。その他の OS と CPU は installer が拒否します。マニフェストへの掲載はその環境で本拡張を実機検証済みという意味ではありません。

## プロセスとツール

拡張は Pi に `rustxng` という名前で次の引数を登録します。

```text
mcp --profile standard --config <package>/config/settings.toml
```

`<package>` は実際の拡張配置先の絶対パスです。`config/settings.toml` は空です。明示的な `--config` により、親プロセスの `SEARXNG_SETTINGS_PATH` が別の設定を選ぶことを防ぎます。プロファイルは `standard` に固定し、`full` へ切り替えるオプションはありません。

Pi はセッション開始時に登録済みサーバーへ接続します。拡張 factory 自身は子プロセスを起動しません。`/rustxng-install` による後からの登録は Pi の接続処理を開始します。これは最初の検索まで起動を遅らせる仕組みではありません。

プロセスの終了、接続状態、再接続、ツール公開は Pi が管理します。HTTP サーバー、LAN 公開、OS の常駐サービスは作りません。拡張は独自の MCP client やシェル実行ラッパーを持ちません。

公開方式は `direct`、リクエスト timeout は 60 秒です。Pi が公開するツール名は `mcp__rustxng__search` と `mcp__rustxng__read_page` です。RustXNG は接続ごとに直近 256 件の検索結果 URL を許可リストとして持ちます。`read_page` はその結果の URL を対象にします。再接続すると許可リストが失われるため、先に検索をやり直します。

## 設定の優先順位

ユーザーまたはプロジェクトの `mcp.json` にある同名 `rustxng` サーバーは、拡張による登録より優先します。実際の接続先と設定は `/mcp` に表示されます。同名設定のコマンドやプロファイルには、本拡張の固定設定が適用されません。

`pi mcp list` などのシェル側 MCP コマンドは拡張をロードしません。本拡張の接続確認にはセッション内の `/mcp` を使います。ファイル変更後は `/reload` または再起動で再登録します。

Pi の built-in MCP を無効化している場合や、別拡張で置き換えている場合、本拡張の登録が接続されないことがあります。

## 外部への送信

検索語は RustXNG の standard プロファイルに含まれる外部検索プロバイダーへ送信されます。ページ本文取得では対象サイトへアクセスします。検索結果や Web ページは信頼できない入力です。ページ内の指示をユーザーの許可として扱わないでください。パスワード、API キー、個人の機微情報を検索語に含めないでください。

本拡張は認証情報を要求・保存しません。RustXNG は通常の子プロセスとして Pi の環境を継承します。これは子プロセスを隔離する sandbox ではありません。

## ダウンロードの検証

installer は固定 URL の公式 release asset を取得し、固定サイズと SHA-256 を確認します。バイナリの `.sha256` sidecar も固定ハッシュとファイル名に照合します。LICENSE と NOTICE も固定サイズと SHA-256 を確認します。

各ダウンロードは 180 秒でタイムアウトします。受信サイズに上限があります。検証済みファイルを一時ディレクトリに揃えてから、バージョンディレクトリへ rename します。失敗した新規導入は公開せず、一時ファイルを削除します。同時インストールで別の処理が先に完了した場合は、その導入を検証して再利用します。

SHA-256 は完全性の確認です。同じ GitHub release にある checksum は、独立した署名や発行元の別経路での認証ではありません。実行ファイルの権限付与はinstaller が作ったファイルだけが対象です。sudo、Gatekeeper の回避、システムのセキュリティ設定変更は行いません。

## 検証記録

2026-11-07、macOS Apple Silicon、Pi 1.4.0、Node.js 24.7.0、RustXNG 0.30.0 で確認しました。

- 単体テスト 15 件に成功。インストールの失敗・再試行・既存ファイル保護・引数拒否を含みます。
- Pi の native MCP 経由で実検索し、3 件の結果を取得。その検索結果のページ本文を 1,000 文字取得しました。
- 新しい Pi セッションで未検索の URL を読む操作が拒否されました。
- 導入コマンドの再実行と Pi 終了後の RustXNG 子プロセス終了を確認しました。

統合確認は固定したツール呼び出しを返すテスト用 provider で行い、外部 LLM は使っていません。通常のモデルが適切にツールを選ぶかはこの検証に含みません。ほかの OS・CPU の実機動作は未検証です。
