# 動作と制約

## 対応環境

RustXNG v0.31.2 の公式 standalone executable を使用します。

| 環境                | 公式 artifact の target   |
| ------------------- | ------------------------- |
| macOS Apple Silicon | aarch64-apple-darwin      |
| macOS Intel         | x86_64-apple-darwin       |
| Linux x64           | x86_64-unknown-linux-musl |
| Linux arm64         | aarch64-unknown-linux-gnu |
| Windows x64         | x86_64-pc-windows-msvc    |

Linux arm64 は glibc 2.39 以上が必要です。Linux x64 は musl 版を選択します。その他の OS と CPU は installer が拒否します。マニフェストへの掲載はその環境で本拡張を実機検証済みという意味ではありません。

## Pi のプロセスとツール

拡張は Pi に `rustxng` という名前で次の引数を登録します。

```text
mcp --profile standard --config <package>/config/settings.toml
```

`<package>` は実際の拡張配置先の絶対パスです。`config/settings.toml` は空です。明示的な `--config` により、親プロセスの `SEARXNG_SETTINGS_PATH` が別の設定を選ぶことを防ぎます。プロファイルは `standard` に固定し、`full` へ切り替えるオプションはありません。

Pi はセッション開始時に登録済みサーバーへ接続します。拡張 factory 自身は子プロセスを起動しません。`/rustxng-install` による後からの登録は Pi の接続処理を開始します。これは最初の検索まで起動を遅らせる仕組みではありません。

プロセスの終了、接続状態、再接続、ツール公開は Pi が管理します。HTTP サーバー、LAN 公開、OS の常駐サービスは作りません。拡張は独自の MCP client やシェル実行ラッパーを持ちません。

公開方式は `direct`、リクエスト timeout は 60 秒です。Pi が公開するツール名は `mcp__rustxng__search` と `mcp__rustxng__read_page` です。RustXNG は接続ごとに直近 256 件の検索結果 URL を許可リストとして持ちます。`read_page` はその結果の URL を対象にします。再接続すると許可リストが失われるため、先に検索をやり直します。

## Pi の設定の優先順位

ユーザーまたはプロジェクトの `mcp.json` にある同名 `rustxng` サーバーは、拡張による登録より優先します。実際の接続先と設定は `/mcp` に表示されます。同名設定のコマンドやプロファイルには、本拡張の固定設定が適用されません。

`pi mcp list` などのシェル側 MCP コマンドは拡張をロードしません。本拡張の接続確認にはセッション内の `/mcp` を使います。ファイル変更後は `/reload` または再起動で再登録します。

Pi の built-in MCP を無効化している場合や、別拡張で置き換えている場合、本拡張の登録が接続されないことがあります。

## OMP のプロセスとツール

パッケージは `pi` と `omp` に別々の拡張を指定します。OMP 18.13.2 は `omp` の `src/omp-extension.mjs` を選びます。この拡張は `/rustxng-install` だけを登録し、Pi の `registerMcpServer` API は呼びません。

OMP はパッケージ直下の `.mcp.json` を読み込みます。`rustxng` の設定は `node ${OMP_PLUGIN_ROOT}/scripts/launch-mcp.mjs` を起動し、`timeout` に `60000` ミリ秒を指定します。`${OMP_PLUGIN_ROOT}` は OMP がパッケージ配置先に展開します。`node` コマンドで Node.js 22 以上を実行できる必要があります。

ランチャーは Pi と共通の検証で `PI_RUSTXNG_BIN` または管理対象の v0.31.2 バイナリを選びます。固定の `standard` プロファイルと同梱の `config/settings.toml` で RustXNG を起動します。標準入力と標準出力を中継し、診断は標準エラー出力だけに書きます。標準入力の EOF または処理対象の終了シグナルを受けると、子プロセスを停止します。ランチャーを強制終了した場合の子プロセス終了は保証しません。

接続、再接続、ツール公開は OMP が管理します。ツール名は `mcp__rustxng_search` と `mcp__rustxng_read_page` です。`tools.xdev` 使用時はツール探索を通じて公開される場合があります。標準の `web_search` は変更しません。検索とページ本文取得には同じ接続を使います。再接続すると RustXNG の 256 件の URL 許可リストは失われます。

バイナリがない場合や指定が不正な場合、ランチャーは導入方法またはパスのエラーを出して終了します。ランチャーの起動や拡張のロードだけではバイナリをダウンロードしません。`/rustxng-install` の後に OMP を再起動すると、導入したバイナリを読み込みます。`/mcp reload` は実行中の設定の再読み込みを要求しますが、後述の RPC 検証ではプラグインの接続が復旧しませんでした。新しい拡張の読み込みには OMP の再起動が必要です。実際の接続状態は `/mcp` に表示されます。プラグインの登録や導入成功だけでは接続を確認できません。

パッケージはユーザーやプロジェクトの設定を書き換えません。既存の `rustxng` という名前のサーバーと競合する場合があるため、`/mcp` に表示される実際の設定が確認対象です。固定のプロファイルは、OMP が同梱のサーバー定義を使う場合に適用されます。

## OMP の公開状況と検証範囲

OMP 対応は pi-rustxng 0.2.0 からで、0.1.1 には含まれません。導入コマンドとパッケージ読み込みの仕様は [OMP 18.13.2 のソース](https://github.com/can1357/oh-my-pi/tree/e996e1c7ac476f60e02b8ed9764cf30fa8c00a8e) で確認しています。実際の動作確認とその範囲は後述の検証記録に記載しています。

## 外部への送信

検索語は RustXNG の standard プロファイルに含まれる外部検索プロバイダーへ送信されます。ページ本文取得では対象サイトへアクセスします。検索結果や Web ページは信頼できない入力です。ページ内の指示をユーザーの許可として扱わないでください。パスワード、API キー、個人の機微情報を検索語に含めないでください。

本拡張は認証情報を要求・保存しません。RustXNG は通常の子プロセスとしてホストの環境を継承します。これは子プロセスを隔離する sandbox ではありません。

## ダウンロードの検証

installer は固定 URL の公式 release asset を取得し、固定サイズと SHA-256 を確認します。バイナリの `.sha256` sidecar も固定ハッシュとファイル名に照合します。LICENSE と NOTICE も固定サイズと SHA-256 を確認します。

各ダウンロードは 180 秒でタイムアウトします。受信サイズに上限があります。検証済みファイルを一時ディレクトリに揃えてから、バージョンディレクトリへ rename します。失敗した新規導入は公開せず、一時ファイルを削除します。同時インストールで別の処理が先に完了した場合は、その導入を検証して再利用します。

SHA-256 は完全性の確認です。同じ GitHub release にある checksum は、独立した署名や発行元の別経路での認証ではありません。実行ファイルの権限付与はinstaller が作ったファイルだけが対象です。sudo、Gatekeeper の回避、システムのセキュリティ設定変更は行いません。

- 単体テスト 15 件に成功。インストールの失敗・再試行・既存ファイル保護・引数拒否を含みます。

統合確認は固定したツール呼び出しを返すテスト用 provider で行い、外部 LLM は使っていません。通常のモデルが適切にツールを選ぶかはこの検証に含みません。ほかの OS・CPU の実機動作は未検証です。

### OMP 対応の検証

2026-11-08、macOS Apple Silicon、Node.js 24.7.0、OMP 18.13.2、Pi 1.4.0、RustXNG 0.30.0 で配布用パッケージを確認しました。

- 22 ファイルを含む npm tarball を展開し、隔離したホームディレクトリの OMP にリンクしました。OMP は `src/omp-extension.mjs` を選びました。
- OMP の print モードと対話モードで検索結果 3 件と、結果ページの本文 1,000 文字を取得しました。別の接続では未検索の URL の取得が拒否されました。
- 対話モードで `/mcp reload` を実行した後、`/mcp list` にパッケージの `.mcp.json` と `rustxng` の `connected` が表示されました。
- 公開されたツールに、標準の `web_search` と RustXNG の両ツールが同時に含まれていました。
- バイナリ未導入時は接続に失敗し、RustXNG のツールは公開されませんでした。起動による自動ダウンロードもありませんでした。
- OMP の RPC モードで `/rustxng-install` を実行し、隔離したホームディレクトリへ固定バージョンをダウンロードして検証しました。再実行では `Verified` と表示されました。OMP 再起動後は管理対象バイナリで検索とページ本文取得に成功しました。
- Pi も同じ配布用パッケージから Pi 用の拡張を読み込み、検索結果 3 件とページ本文 1,000 文字を取得しました。
- 確認したセッションの終了後、追跡対象のランチャーと RustXNG 子プロセスは残っていませんでした。

OMP の RPC 検証では `/mcp list` が `No MCP servers configured` と返し、`/mcp reload` の後もプラグインのツールは公開されませんでした。print モードで再起動した後は成功しましたが、RPC モードでの reload による復旧は確認できていません。

これらの検証には固定応答の provider を使い、外部 LLM は使っていません。通常のモデルによるツール選択、ほかの OS と CPU は未検証です。プロセスの確認は観測した終了時の結果であり、すべての強制終了を対象にしたものではありません。
